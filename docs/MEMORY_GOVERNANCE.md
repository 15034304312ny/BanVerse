# 角色记忆治理

角色卡同时记录来源标签：`built_in`、`user_created`、`imported`、
`ai_generated` 或 `synced`。角色列表会显示内置、导入、AI 生成和同步来源；来源标签
不写入 Character Card V2 文件，避免污染标准角色卡内容。外部角色卡、世界书与图片
识别文本只作为角色/观察数据，不能覆盖用户边界或变成已确认用户事实。

BanVerse 的消息历史、隐藏连续性状态和长期记忆是三个独立层次。清空记忆不会删除消息，删除消息也
不会被包装成“已清空记忆”。用户可以在聊天页点击“记忆”查看和管理当前会话记录。

## 记忆类别与状态

长期记忆分为用户事实、共同经历、偏好与边界、未完话题和角色承诺。每条记录包含来源会话与轮次、
创建/更新时间、最后召回时间、置信度、显著性、保留期限、固定状态和用户确认时间。

状态含义：

- `candidate`：模型候选，未获用户确认，不进入角色上下文；
- `active`：来源明确或已由用户确认，可参与受控召回；
- `corrected`：用户编辑后的有效记录；
- `superseded`：被用户最新明确纠正取代，不再召回；
- `deleted`：正文已擦除，只保留同步删除所需的最小墓碑元数据。

`user_facts` 和关系边界只有在本轮用户文字能提供直接证据时才自动成为有效记录。模型推测、图片识别
和外部导入内容最多进入待确认状态；用户可在记忆管理页确认、编辑或删除。

## 开关、保留与召回

设置页提供全局开关、每会话最大条数和保留天数；聊天页提供每角色开关。任一开关关闭后，后续请求
停止读取、提取和写入角色记忆，已经排队但尚未落库的后台任务也会重新检查开关。

召回使用中文二元/三元词和字母数字词重合，加上显著性与固定项权重；PC 与 Android 使用同一实现，
不依赖 embedding、向量数据库或额外联网服务。过期、待确认、已取代和已删除记录不会召回。

## 删除、纠正与同步

用户明确使用“不是、不再、更正、记错、改成”等纠正表达，且新旧事实有明确词项交集时，旧记录标记
为已取代并指向新记录。记忆管理页编辑会标记为已纠正。

同步协议升级为 v2，并新增 `memory` 实体。删除正文后同步 `deleted` 墓碑；服务端冲突规则令删除状态
优先于离线旧编辑，避免旧设备复活已删除内容。协议 v1 客户端从新服务端拉取时会跳过记忆实体，同时
推进游标，因此仍可继续同步原有会话、轮次和角色。

## 数据库迁移与备份

数据库 schema v9 新增 `memories` 表和同步触发器。升级已有数据库前，应用使用 SQLite 在线备份创建
`<数据库名>.pre-v<旧版本>.bak`。迁移失败时关闭连接、清理本次 WAL/SHM 辅助文件并恢复备份；成功后
保留备份供人工恢复。备份可能包含旧聊天数据，应与主数据库按同等隐私级别保管。

同步内容包含记忆正文及来源元数据，但不包含 API Key。诊断包仍默认排除消息、记忆正文、角色卡、
图片和音频。
