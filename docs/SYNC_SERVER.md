# BanVerse 双端消息同步

BanVerse 使用“本地 SQLite + 中央同步服务”的本地优先方案。Windows 和 Android
都保留完整本地数据，离线时可继续使用；恢复网络后，客户端会在后台推送增量并
拉取另一端的变化。1.3.0 默认连接 BanVerse 官方 HTTPS 服务
`https://47.102.121.29`，也可以改为自托管服务。

## 同步范围

| 数据 | 是否同步 |
| --- | --- |
| 角色卡、角色头像 | 是 |
| 会话、消息、摘要、角色连续性状态 | 是 |
| 用户聊天图片、角色生成图片 | 是，按 SHA-256 去重和校验 |
| 文本/图片/TTS API Key | 否 |
| TTS 音频缓存、模型列表缓存、界面偏好 | 否 |

本地消息、角色、摘要或图片变化会在约 1.2 秒内合并并触发同步，客户端另以每
15 秒轮询兜底，也可以在设置页点击“立即同步”。每条变化都有幂等事件 ID；
服务端用单调修订号提供增量游标。删除使用墓碑传播。两台设备离线修改同一
实体时，服务端先接受的版本成为当前版本，另一份内容会保存在本机
`sync_conflicts` 表中，不会静默丢弃。主动消息使用短期租约，避免电脑和手机同时
以同一角色发出两条主动消息。

## 启动自托管服务

建议在独立 Python 虚拟环境运行：

```powershell
py -m venv .sync-venv
.\.sync-venv\Scripts\python.exe -m pip install -e ".[sync-server]"
.\.sync-venv\Scripts\banverse-sync-server.exe
```

默认监听 `127.0.0.1:8765`，数据保存在当前系统用户的
`.banverse-sync` 目录：

- `sync.db`：账户、设备、实体、修订记录和租约；
- `media/`：按账户及 SHA-256 隔离的媒体对象。

也可以指定目录和端口：

```powershell
.\.sync-venv\Scripts\banverse-sync-server.exe `
  --host 127.0.0.1 --port 8765 --data D:\BanVerseSync
```

若不希望任何访问者自行创建账户，请在启动前设置注册口令：

```powershell
$env:BANVERSE_SYNC_REGISTRATION_SECRET = "请替换为足够长的随机值"
.\.sync-venv\Scripts\banverse-sync-server.exe
```

此时应用“创建账户”时也要填写相同的“注册口令”。注册口令只用于创建账户，
不会保存到客户端设置。

## 公开部署

内置服务不负责 TLS。需要跨公网同步时，应让服务只监听回环地址，并用 Caddy、
Nginx 或同类反向代理提供有效的 HTTPS 证书，再在 BanVerse 中填写外部
`https://` 地址。不要把未加密 HTTP 暴露到公网。

当前协议不是端到端加密：自托管服务管理员可以读取同步的角色、消息和图片。
因此应自行保护服务器账户、数据库、媒体目录和备份。同步账户令牌等同于账户
密码，只在创建时返回一次；请妥善备份，不要提交到 GitHub、Issue 或日志。

仅在可信局域网临时测试时，可以监听所有网卡：

```powershell
.\.sync-venv\Scripts\banverse-sync-server.exe --host 0.0.0.0 --port 8765
```

Windows 防火墙只应允许“专用网络”。手机端需填写电脑的局域网 IP，而不是
`127.0.0.1`。部分 Android 系统会阻止明文 HTTP；正式双端使用仍应配置 HTTPS。

## 配对电脑和 Android

1. 在第一台设备打开“设置 → 双端消息同步”。使用官方服务时需要邀请注册口令；
   自托管服务则填写自己的地址和注册口令，然后点击“创建账户”。
2. 创建成功后点击“复制配对信息”。复制内容包含服务地址、账户 ID 和令牌。
3. 通过你信任的私密方式把配对信息转移到自己的另一台设备。
4. 在第二台设备复制整段 JSON，点击“从剪贴板导入配对”。应用会校验并保存凭据、
   启用同步，然后清除剪贴板中的令牌；也可以手动填写后点击“保存并连接”。
5. 两端分别点击一次“立即同步”。首次同步会上传当前本地快照，后续只传增量。

断开账户只会清除本机同步游标和令牌，不会删除本地聊天，也不会删除服务器数据。
若要更换到一个全新的同步账户，断开后重新创建或填写新账户即可。

## 备份与健康检查

停止同步服务后，完整备份数据目录即可同时保存数据库和媒体。恢复时应保持原目录
结构。服务健康检查地址为：

```text
GET /v1/health
```

正常响应包含 `status: ok`、当前协议版本和 `server_version`。生产环境还应限制
请求体大小、记录可用性指标，并定期验证备份能否恢复。
