# BanVerse 界面设计规范

BanVerse 采用“熟悉的即时通讯结构 + 温暖的 AI 陪伴气质”。布局借鉴微信、
QQ 等成熟产品的信息层级与操作习惯，但不复制其品牌素材、图标或配色。

## 设计能力与参考

本轮加载已有的 `ckm:design-system` 和 `ckm:ui-styling` 设计技能，应用统一
颜色令牌、组件状态、响应式布局与可访问性检查；没有安装新的外部插件或
向应用引入 React / Tailwind 等运行时依赖。

查阅了微信官方 [WeUI](https://github.com/Tencent/weui) 的设计参考。
WeUI 面向移动 Web，BanVerse 则继续使用原生 PySide6 / Qt 实现双端组件，
保持当前打包方式以及文本、图片、TTS、同步等业务接口不变。

## 设计原则

1. **对话优先**：消息、角色状态与输入区始终处于视觉主层级。
2. **少即是多**：低频的编辑、删除、导入和导出操作收进“更多”菜单。
3. **身份清晰**：每条消息显示发送者姓名和头像，用户与角色左右分列。
4. **双端一致**：桌面端使用导航栏、会话栏、聊天区三栏结构；Android
   使用单页内容和底部导航，但共享颜色、间距、气泡及组件状态。
5. **可访问**：移动端触控区不小于 44 px，图标按钮均提供可访问名称和提示，
   文本与背景对比度以 WCAG AA 为目标。

## 视觉系统

- 品牌主色：翡翠绿，表达陪伴、生命力与安全感。
- 浅色主题：暖白侧栏、浅灰绿聊天背景、白色角色气泡、淡绿色用户气泡。
- 深色主题：墨绿色导航和背景，使用高亮绿色表达选中、焦点和在线状态。
- 圆角：输入与列表 8–12 px，卡片与输入容器 16 px，胶囊按钮 22 px。
- 间距：以 4 px 为基础单位，组件主要采用 8、12、16、20、24 px。
- 状态：所有主要控件具备默认、悬停、按下、焦点、禁用状态；危险操作使用
  独立红色语义色。

主题令牌集中在 `src/deepseek_cli/desktop/theme/tokens.py`，分为基础、语义和
组件三层。组件样式集中在 `src/deepseek_cli/desktop/theme/styles.py`。

## 核心布局

### 桌面端

- 80 px 深色导航栏：品牌、消息、角色、设置。
- 320 px 会话栏：新建、搜索、头像、姓名、AI 摘要和最近时间。
- 自适应聊天区：角色头部、模型胶囊、更多菜单、消息流和底部输入区。

### Android

- 消息列表与聊天详情分页显示，聊天头部提供明确的返回入口。
- 底部导航保持 44 px 以上触控区域，使用平台无关的矢量线性图标。
- 聊天头部首行呈现返回、头像、标题与更多菜单；模型独立一行，避免挤压角色名。
- 输入区采用“附件—输入—表情—发送”横向结构，在 320 px 宽度仍可操作。

## 组件约定

- 消息气泡按内容自然收缩，达到最大宽度后自动换行；不会用大块固定面板包裹
  短消息。
- 角色消息靠左，用户消息靠右；头像和发送者姓名与气泡作为一个整体对齐。
- 会话列表正文仅显示 AI 摘要，时间使用“HH:mm / 昨天 / MM/DD”格式。
- 模型选择器是会话级设置，始终位于聊天头部；编辑、记忆与删除属于二级操作。
- 模型胶囊显示实际模型名，下拉列表保留平台完整说明；超长名称中间省略，
  提示和可访问描述始终保留全名，不将 GRS AI 的内部兼容别名当成实际模型。
- 图片预览随气泡缩放，始终从原图重新采样；缩窄窗口不会裁掉图片。
- 角色页只保留“新建”和“开始聊天”为显式操作，其余管理动作放入二级菜单。

## 验收尺寸

- 320×480：核心聊天与返回操作可用，无水平滚动。
- 390×780：常见手机尺寸，标题、模型和更多按钮不重叠。
- 900×620：桌面端最小窗口，三栏布局完整。
- 1180×760：桌面推荐尺寸，消息阅读宽度舒适。

验收区分自动化布局测试、桌面 Qt 的手机尺寸预览与 Android 实机验收。
手机尺寸预览不代表已完成安卓打包或实机触控测试；发布前仍须在实机检查
系统字体、软键盘、安全区域、返回手势和滚动到上下边界的行为。

本轮源码验证：Ruff 检查通过，完整回归 **314 项通过**（含 43 项界面测试）。
回归覆盖模型平台显示、移动端附件选择器、边界滚动夹取及图片气泡自适应等。
这不等同于调用全部真实供应商 API 的线上验收。
