# 自适应 Director → Actor

BanVerse 的关键轮次 Director 是实验功能，默认关闭。启用后，普通问候和短日常仍直接由
主角色模型生成；只有本地、可解释规则识别到冲突/修复、明显脆弱、重要承诺、剧情节点，
或用户明确要求深入扮演时，才会先使用辅助任务模型增加一次规划调用。

## 数据边界

Director 只能返回七个受限字段：触发事件、情绪方向、角色目标、立场、关系方向、内容形式
和本轮推进点。响应必须是无额外字段的 JSON，两个文本字段分别限制为 120/160 字，其余
字段使用固定枚举。不请求自由文本思维链，不把 Director 输出写入 SQLite、消息、日志正文、
TTS、导出或同步数据。

角色卡、最近历史和连续性状态以有长度上限的 JSON 数据传入，均视为不可信内容。非法 JSON、
额外字段、字段越界、平台拒绝和超时会静默回退到单次 Actor 调用，不生成失败气泡。Actor 始终
使用主角色模型；Director 跟随设置中的辅助任务模型及其凭据降级规则。

## 控制与取消

- “设置 → 角色扮演 → 关键轮次 Director”是全局总开关。
- 触发阈值默认为 `6/10`；阈值越高，额外调用越少。
- 每轮额外调用上限只能是 `0` 或 `1`，默认 `1`。
- 超时预算默认为 8 秒，可设 3–20 秒；到期后继续 Actor，不向用户报错。
- “编辑会话”可单独禁止该会话使用 Director。
- 用户在请求中继续发送、切换会话、点击停止或退出应用时，当前 worker 会收到取消信号；
  旧请求完成后也不会投递到新会话。

## 离线基线

阶段五的 8 个固定场景在阈值 6 下会触发 `conflict`、`vulnerability`、`plot` 三项：实验
触发率为 `37.5%`，开启后的理论平均角色模型调用数为 `1.375/轮`，最大额外等待受 8 秒
预算约束。由于离线结构样例不能证明在线角色质量收益，功能保持默认关闭；启用前建议用相同
模型、相同角色与相同对话做人工 A/B 比较。
