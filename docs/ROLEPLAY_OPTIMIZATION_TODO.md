# BanVerse 角色扮演深度优化 TODO

目标：在不破坏现有文本、图片、TTS、主动消息、双端同步和 Character Card V2
兼容性的前提下，让角色回复具备更稳定的人格辨识度、情绪因果、关系连续性、生活主动性
与自然聊天节奏。

## 阶段一：生成链路与表达质量

- [x] 将 Character Card V2 的 `post_history_instructions` 从前置 system prompt
  移到最近历史之后、当前用户消息之前，保证角色专属约束具有足够的近因权重。
- [x] 增加不展示给用户的“导演节拍”规划：识别触发事件、当前情绪、角色目标、立场、
  潜台词、关系方向和本轮要推进的一件事，再输出角色可见内容。
- [x] 将全局角色提示从大量禁止项改为正向行为规则；保留用户自主权、边界和图片事件约束。
- [x] 为请求管线增加独立的历史后提示字段，覆盖桌面聊天、主动消息和 AI 开场三条入口。
- [x] 将模型参数从固定模型 ID 判断改为“角色聊天/推理模型能力”判断；推理模型保持供应商
  兼容设置，普通聊天模型使用角色创造性参数。
- [x] 将固定 72 字切分改为语义切分：优先保留段落、引号、语气转折、句末停顿与括号动作，
  只对超长内容做安全兜底。
- [x] 保证分段只改变投递节奏，不改写台词、不吞图片事件、不把括号内对白误当 TTS 台词。

验收：角色专属历史后指令出现在最终用户消息之前；同一完整情绪句不会因固定长度被截断；
聊天、主动消息、开场消息均通过原有状态机投递。

## 阶段二：情绪、关系与角色当前状态

- [x] 扩展 `role_state`，保留旧字段并新增：主/次情绪、触发原因、强度、惯性、角色目标、
  当前顾虑、未说出口的倾向、关系信任/亲密/紧张及最近变化。
- [x] 为数值字段增加范围约束，为文本和数组增加长度限制，错误模型输出安全回退。
- [x] 在连续性记录器提示中明确“情绪变化必须有原因、不能每轮重置、关系变化来自事件”。
- [x] 将扩展状态注入角色提示时转换为易读的导演上下文，不要求角色直接宣读情绪标签。
- [x] 记录状态对应的最后处理轮次，防止异步摘要结果覆盖更新较新的状态。
- [x] 保持旧数据库、旧同步数据和旧版 `role_state_json` 可直接读取，无需破坏性迁移。

验收：旧状态 JSON 仍可加载；非法强度被限制；连续两轮之间可以追踪情绪原因和关系变化；
旧后台任务不能覆盖新任务状态。

## 阶段三：轻量长期记忆检索

- [x] 最近原文窗口调整为 12 个完整轮次，为角色卡、导演上下文和召回记忆保留上下文空间。
- [x] 在 SQLite 现有消息上实现本地轻量召回，不引入移动端大型 embedding 依赖。
- [x] 从较早轮次按中文二元词、字母数字词、未完话题、角色目标和情绪线索计算相关度。
- [x] 召回结果排除最近原文窗口，限制条数和字符数，并标注为“较早共同经历”。
- [x] 当前用户消息为空时，主动消息使用 `open_threads`、角色当前目标和共同记忆构造召回查询。
- [x] 提示模型仅在相关时自然延续记忆，不复述数据库摘要，不把推测当作事实。
- [x] 保持同步协议不变：记忆来自已同步 turns 与 `role_state_json`，不新增敏感云端字段。

验收：较早但相关的事件可被召回；无关旧消息不进入提示；短会话与空查询安全返回空列表；
Android 不新增原生依赖。

## 阶段四：角色卡样例与质量回归

- [x] 为每个内置角色把示例扩展为多轮片段，覆盖分享、分歧、犯错、沉默、关系修复、
  主动生活和拒绝越界，不只展示一句式口头风格。
- [x] 保持六个角色在相同用户输入下的决策差异，而不只是替换名字、职业和修辞。
- [x] 为角色提示顺序、导演节拍、扩展状态、长期召回和语义分段补充单元测试。
- [x] 增加离线角色扮演回归样例集，覆盖日常、冲突、脆弱、回忆、主动消息和剧情推进。
- [x] 增加可重复的结构指标：角色卡区分度、固定开头重复、每轮强制提问、情绪无因跳变、
  用户事实矛盾和格式泄漏。
- [x] 运行 Ruff、完整 pytest 和版本一致性检查；不修改版本号、不打包，除非另行要求。

验收：六张内置卡均有多轮示例；新增回归测试通过；原有图片、TTS、同步、安卓打包测试不回退。
