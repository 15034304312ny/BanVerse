# BanVerse 角色扮演深度优化 TODO

目标：在不破坏现有文本、图片、TTS、主动消息、双端同步和 Character Card V2
兼容性的前提下，让角色回复具备更稳定的人格辨识度、情绪因果、关系连续性、生活主动性
与自然聊天节奏。

## 阶段一：生成链路与表达质量

- [x] 将 Character Card V2 的 `post_history_instructions` 从前置 system prompt
  移到最近历史之后、当前用户消息之前，保证角色专属约束具有足够的近因权重。
- [x] 增加不展示给用户的“导演节拍”规划：识别触发事件、当前情绪、角色目标、立场、
  潜台词、关系方向和本轮要推进的一件事，再输出角色可见内容。
- [x] 将全局角色提示从大量禁止项改为正向行为规则；保留用户自主权、边界和图片事件约束。
- [x] 为请求管线增加独立的历史后提示字段，覆盖桌面聊天、主动消息和 AI 开场三条入口。
- [x] 将模型参数从固定模型 ID 判断改为“角色聊天/推理模型能力”判断；推理模型保持供应商
  兼容设置，普通聊天模型使用角色创造性参数。
- [x] 将固定 72 字切分改为语义切分：优先保留段落、引号、语气转折、句末停顿与括号动作，
  只对超长内容做安全兜底。
- [x] 保证分段只改变投递节奏，不改写台词、不吞图片事件、不把括号内对白误当 TTS 台词。

验收：角色专属历史后指令出现在最终用户消息之前；同一完整情绪句不会因固定长度被截断；
聊天、主动消息、开场消息均通过原有状态机投递。

## 阶段二：情绪、关系与角色当前状态

- [x] 扩展 `role_state`，保留旧字段并新增：主/次情绪、触发原因、强度、惯性、角色目标、
  当前顾虑、未说出口的倾向、关系信任/亲密/紧张及最近变化。
- [x] 为数值字段增加范围约束，为文本和数组增加长度限制，错误模型输出安全回退。
- [x] 在连续性记录器提示中明确“情绪变化必须有原因、不能每轮重置、关系变化来自事件”。
- [x] 将扩展状态注入角色提示时转换为易读的导演上下文，不要求角色直接宣读情绪标签。
- [x] 记录状态对应的最后处理轮次，防止异步摘要结果覆盖更新较新的状态。
- [x] 保持旧数据库、旧同步数据和旧版 `role_state_json` 可直接读取，无需破坏性迁移。

验收：旧状态 JSON 仍可加载；非法强度被限制；连续两轮之间可以追踪情绪原因和关系变化；
旧后台任务不能覆盖新任务状态。

## 阶段三：轻量长期记忆检索

- [x] 最近原文窗口调整为 12 个完整轮次，为角色卡、导演上下文和召回记忆保留上下文空间。
- [x] 在 SQLite 现有消息上实现本地轻量召回，不引入移动端大型 embedding 依赖。
- [x] 从较早轮次按中文二元词、字母数字词、未完话题、角色目标和情绪线索计算相关度。
- [x] 召回结果排除最近原文窗口，限制条数和字符数，并标注为“较早共同经历”。
- [x] 当前用户消息为空时，主动消息使用 `open_threads`、角色当前目标和共同记忆构造召回查询。
- [x] 提示模型仅在相关时自然延续记忆，不复述数据库摘要，不把推测当作事实。
- [x] 保持同步协议不变：记忆来自已同步 turns 与 `role_state_json`，不新增敏感云端字段。

验收：较早但相关的事件可被召回；无关旧消息不进入提示；短会话与空查询安全返回空列表；
Android 不新增原生依赖。

## 后续优化路线

以下项目从阶段五开始，均为尚未实施的候选工作，不构成固定版本承诺。实施时优先保证
旧数据库、Character Card V2、同步协议、PC/Android 配置与现有文本、图片、TTS 功能兼容。

优先级说明：

- **P0**：发布可靠性、数据安全或后续评估所必需，应最先完成。
- **P1**：直接改善角色扮演质量和用户可控性，作为下一主版本重点。
- **P2**：体验、性能和多模态一致性增强，可按平台能力分批交付。
- **P3**：长期基础设施或探索性工作，应先形成设计文档再决定是否开发。

### 推荐实施顺序

| 顺序 | 阶段 | 优先级 | 首个可交付成果 | 主要依赖 |
| --- | --- | --- | --- | --- |
| 1 | 阶段五：基线与诊断 | P0 | 可重复的本地回放基线与脱敏诊断包 | 当前 v1.4.0 |
| 2 | 阶段六：模型职责与能力 | P1 | 主角色/辅助任务模型可独立配置 | 阶段五 |
| 3 | 阶段八：记忆治理 | P1 | 用户可查看、纠正和删除角色记忆 | 阶段五 |
| 4 | 阶段七：自适应双阶段生成 | P1 | 仅关键轮次启用 Director → Actor | 阶段六、阶段十一基线 |
| 5 | 阶段九：关系边界与主动消息 | P1/P2 | 每角色边界、静默时段和主动消息策略 | 阶段八 |
| 6 | 阶段十：多模态一致性 | P2 | 图片、文字、TTS 使用同一场景和事件状态 | 阶段六 |

## 阶段五：发布基线、可观测性与诊断（P0）

目标：先回答“哪类回复变好了、代价增加了多少、失败发生在哪一步”，避免后续优化只能凭主观感受。

- [x] 固定一套不含真实用户数据的离线回放场景，覆盖六个内置角色、普通聊天、冲突、安慰、
  事实纠正、长会话、主动消息、图片事件和 TTS 分段。
- [x] 建立供应商/模型测试矩阵，记录模型 ID、平台、请求模式、启用能力与应用版本；测试数据中
  不写入 API Key、访问令牌、真实聊天或用户媒体。
- [x] 为一次回复的关键阶段增加本地诊断事件：构造上下文、调用角色模型、解析回复、分段、
  图片决策、TTS、消息落库和同步；每个事件记录耗时、结果类型和脱敏错误码。
- [x] 区分角色主调用、摘要/状态更新、图片判断、图片生成和 TTS 失败，不再只显示笼统的
  “服务暂时不可用”。用户界面保持简洁，详细信息放入可复制诊断页。
- [x] 增加用户主动触发的“导出诊断包”，默认排除消息正文、角色私密设定、图片、音频、Key、
  Token、Cookie 和设备账号；导出前展示包含项并允许取消。
- [x] 统计本地 `p50/p95` 首段可见时间、完整回复时间、每轮模型调用次数、失败率和取消率，
  为普通单调用与关键轮次双调用分别建立基线。
- [x] 为后台摘要、主动消息和状态更新添加来源轮次、任务 ID 与取消原因，便于定位过期任务覆盖问题。
- [x] 禁止默认上传遥测；若未来增加远程崩溃报告，必须独立征得同意并提供关闭和删除入口。

关键文件：`roleplay_quality.py`、`desktop/flow.py`、`desktop/background.py`、桌面诊断 UI、
`tests/resources/roleplay_regression_cases.json`。

验收：默认测试和 CI 不访问外网；同一回放输入可生成可比较结果；诊断包扫描不到密钥和消息正文；
取消或失败可以定位到具体阶段；旧版本用户无需迁移配置即可继续聊天。

## 阶段六：主角色模型、辅助任务模型与能力协商（P1）

目标：把“说话的角色”和“做摘要、记忆、分类等后台工作”的模型职责分开，同时避免向供应商发送
不支持的参数。

- [x] 在文本设置中增加“主角色模型”和“辅助任务模型”；辅助模型默认选择“跟随主角色模型”，
  升级后保持现有行为和调用平台不变。
- [x] 明确辅助模型使用范围：摘要、角色状态、记忆候选、图片意图判断、主动消息计划和头像提示词；
  用户可见的角色正文不得被静默切换到辅助模型。
- [x] 后台辅助调用失败时采用非阻塞降级：可回退到主模型或跳过本次辅助任务，但不能阻断已经成功的
  角色回复；回退策略在设置页明确显示。
- [x] 从平台模型列表建立统一能力描述，至少包含文本生成、视觉理解、推理模式、流式响应、
  上下文长度和可用采样参数；未知模型使用保守能力集。
- [x] 按供应商和模型能力开放 `temperature`、`top_p`、频率/存在/重复惩罚等参数；未声明支持的字段
  不发送，供应商默认值不被无意义覆盖。
- [x] 将角色创造性预设转换为能力安全的请求参数，并允许高级用户恢复平台默认值。
- [x] 设置页只在选择对应平台后显示其 Key、Base URL、模型和高级参数；模型拉取失败时保留已保存值，
  不清空用户配置。
- [x] 在模型选择旁显示能力、预估用途和“主/辅助”标签，避免多模态模型被误用于不支持的图片接口。
- [x] 为旧设置迁移、平台切换、模型列表失败、能力未知和辅助模型降级补充测试。

关键文件：`desktop/ui/pages/settings_page.py`、模型发现与配置模块、`desktop/background.py`、
`chat_service.py`、各平台 gateway。

验收：升级后默认行为不变；主模型与辅助模型可使用不同平台；辅助服务失败不吞掉角色正文；
请求抓包中不存在目标平台不支持的字段；PC 与 Android 使用兼容的配置字段和默认值。

## 阶段七：自适应 Director → Actor 生成（P1）

目标：只在高价值轮次增加一次受控规划调用，提高冲突、情绪转折和剧情推进质量，不让普通日常聊天
承担双倍延迟与费用。

- [x] 定义有限、可校验的“导演节拍契约”，只包含触发事件、情绪方向、角色目标、立场、关系方向、
  内容形式和本轮推进点；不请求、不保存、不同步自由文本思维链。
- [x] 设计可解释的触发器：高情绪强度、关系变化、冲突、重要承诺、剧情节点或用户显式要求深入扮演；
  普通问候和短日常默认保持单调用。
- [x] 增加全局与每会话开关、触发阈值、最大额外调用次数和超时预算；默认使用保守配置。
- [x] Director 可使用辅助任务模型，Actor 始终使用主角色模型；导演结果只作为隐藏结构化上下文，
  不能直接显示、写入消息或进入 TTS。
- [x] 对 JSON 非法、字段越界、超时、取消和供应商拒绝做单调用降级，不产生失败气泡或残留“正在输入”。
- [x] 在用户继续发送、切换会话、退出应用时取消旧任务，禁止旧导演结果进入新轮次。
- [x] 增加导演内容泄漏、角色卡注入、超长规划、双调用重复回复和超时回退测试。
- [x] 用阶段五基线比较触发率、平均调用数、首段可见时间和角色质量；收益不明确时保持实验开关关闭。

关键文件：`character_prompt.py`、`chat_service.py`、`desktop/flow.py`、工作线程与取消逻辑、
`roleplay_quality.py`。

验收：普通轮次只调用一次角色模型；关键轮次最多增加一次规划调用；导演失败仍能返回正常角色回复；
任何可见消息、日志、导出和同步数据中都不出现隐藏规划；取消后无跨会话串写。

## 阶段八：长期记忆治理与用户可编辑记忆（P1）

目标：从“按旧消息临时召回”演进到可追溯、可纠正、可删除的轻量记忆，同时把隐私控制权交给用户。

- [x] 将记忆候选分为已确认用户事实、共同经历、偏好与边界、未完话题和角色承诺；禁止把模型推测
  自动提升为已确认事实。
- [x] 每条持久记忆记录来源会话/轮次、创建时间、最后使用时间、置信度、显著性和状态
  （有效、已纠正、已取代、已删除）。
- [x] 当用户明确纠正事实时，旧记忆立即标记为已取代；召回时优先用户最近的明确陈述。
- [x] 增加每会话“记忆管理”页，支持查看、搜索、编辑、删除、固定、批量清理和仅重置角色连续性；
  “清空消息”与“清空记忆”必须是两个独立操作。
- [x] 支持全局与每角色记忆开关、保留期限和最大条数；关闭后停止读取、提取和写入，不只隐藏 UI。
- [x] 召回仍以轻量词法方案作为 PC/Android 共同基线；可选桌面索引只能作为加速器，结果和无索引模式
  保持可接受的一致性，不能成为移动端必需依赖。
- [x] 为导入角色卡、同步数据和图片识别文本标记信任来源，防止外部内容伪装成用户事实或系统指令。
- [x] 若同步独立记忆记录，先升级协议版本，设计增量迁移、删除墓碑、冲突规则和旧客户端降级；
  未完成协议设计前继续从 turns 与 `role_state_json` 派生，不新增云端敏感字段。
- [x] 为记忆关闭、事实纠正、删除后同步、旧数据库迁移、双设备冲突和大量历史召回补充测试。

关键文件：数据库迁移与 repository、记忆召回模块、记忆管理 UI、同步协议与服务端迁移、
`tests/test_repositories.py`。

验收：用户可以知道一条记忆从哪里来并永久删除；明确纠正不会被旧事实反复覆盖；关闭记忆后无新写入；
旧数据库可迁移且迁移失败可恢复备份；Android 不增加大型 embedding 或必须联网的记忆依赖。

## 阶段九：关系节奏、内容边界与主动消息（P1/P2）

目标：让关系发展和主动联系更贴合用户偏好、时间与共同经历，同时避免打扰、操控感和隐藏数值游戏化。

- [x] 增加全局默认值和每角色覆盖项：关系发展速度、称呼偏好、允许话题、禁止话题、主动消息频率、
  每日上限和静默时段。
- [x] 不直接展示“亲密度 87”之类隐藏分数；设置页展示的是用户可理解、可修改的策略与边界。
- [x] 角色状态变化保持缓慢并绑定明确事件；普通寒暄不能造成剧烈信任或亲密变化。
- [x] 主动消息综合本地时间、工作日/周末、用户作息、未完话题、角色生活和上次互动时间；没有依据时
  不声称真实天气、地理位置或用户正在做某件事。
- [x] 增加重复抑制、冷却时间、每日上限和敏感场景抑制，避免连续问候、催回复或在用户拒绝后继续追问。
- [x] 提供每角色静音、暂停一天、暂停至指定时间和“为什么收到这条消息”的简短说明。
- [x] 双端同步使用服务端租约或幂等事件 ID，确保 PC 与手机在线时同一主动消息只发送一次。
- [x] 角色表达亲密时不得制造愧疚、威胁离开、诱导依赖或绕过用户明确边界；将相关样例加入回归集。
- [x] 为时区切换、夏令时、跨午夜、应用休眠恢复、双设备竞争、禁用开关和每日上限编写确定性测试。

关键文件：主动消息调度器、角色状态、设置页、同步事件/租约接口、后台任务。

验收：静默时段和每日上限严格生效；双端只产生一条主动消息；禁用后不再调模型；主动消息能自然延续
已有话题但不捏造外部事实；用户边界在角色卡提示之上保持最高优先级。

## 阶段十：文本、图片与 TTS 的多模态一致性（P2）

目标：三类输出共享同一场景、人物状态和事件顺序，任何一个服务失败都不会破坏正常文字聊天。

- [x] 为角色维护稳定的视觉身份描述和负面约束；只有平台声明支持时才使用参考图、图生图或视觉一致性能力。
- [x] 图片提示词使用当前本地时间段、已知场景、角色服装和最近事件；未知天气、位置和现实状态不得编造。
- [x] 视觉理解先输出结构化观察、置信度和不确定项，再交给角色自然回应；低置信度文字、人脸身份和敏感属性
  不作肯定陈述。
- [x] 图片触发继续并行使用语义判断和关键词，但增加预算、冷却、去重和用户边界；同一轮只能创建一个
  幂等图片事件。
- [x] 自动生图前检查角色动作是否真正包含发送图片意图，避免把“想象一张图”或历史引用误判为新图片。
- [x] 文本分段结果作为消息、图片事件和 TTS 的唯一事件源，禁止三条管线各自重新拆分导致顺序不一致。
- [x] TTS 仅朗读角色台词，继续排除旁白、括号动作、图片指令和控制标记；不再让 AI 注入停顿、拼音、
  轻重音、语速或音量标签。
- [x] 图片/TTS 超时或失败时保留已成功的文字段落，显示可重试状态并清除“正在生成/正在输入”。
- [x] 为混合台词与动作、连续图片意图、用户上传图片、低置信度 OCR、TTS 取消和乱序完成补充测试。

关键文件：回复分段器、图片决策与生成服务、视觉理解 gateway、TTS 文本提取、消息事件队列。

验收：文字、图片和语音按模型原始语义顺序逐段出现；动作与旁白不被朗读；图片失败不阻断文字；
角色外观在支持参考图的平台上保持可辨识一致，不支持的平台自动降级。

## 阶段十一：角色质量评估与发布门禁（P1，持续进行）

目标：把“更拟人”拆成可重复检查的结构指标和人工评价，防止为了某个角色优化而让其他角色退化。

- [ ] 将离线样例扩展到每个内置角色，覆盖 20+ 轮长会话、事实纠正、重复追问、冲突修复、拒绝越界、
  沉默、时间感、图片、主动消息、中英混合和供应商异常。
- [ ] 在现有指标上增加：固定安慰模板、过度道歉、提问密度、动作描写密度、回复长度分布、关系无因跳变、
  记忆命中精确率/召回率、边界遵从和多模态事件一致性。
- [ ] 为六个角色定义“决策差异”断言：相同输入下至少在目标、立场、行动或关系策略上存在可解释差异，
  不只比较词汇和口头禅。
- [ ] 只把确定、稳定、无外网依赖的检查设为 CI 硬门禁；模型随机输出和第三方可用性不得直接造成主分支失败。
- [ ] 提供手动在线评估命令，固定评审模型、提示版本、温度和匿名化规则；记录成本与结果，但默认不在 CI 运行。
- [ ] 建立人工 A/B 盲测表，评价人格辨识度、情绪因果、关系连续性、自然节奏、创造性、边界和总体偏好，
  每次只比较一个明确改动。
- [ ] 发布前对 DeepSeek、GRSAI 及已配置兼容平台执行最小冒烟矩阵；缺少凭据时明确跳过而不是伪造通过。
- [ ] 保存每个版本的基线结果和允许波动范围；低于阈值时标记阻塞项并附具体失败样例。

关键文件：`roleplay_quality.py`、`tests/test_roleplay_quality.py`、回归样例集、手动评估脚本和发布检查清单。

验收：默认 CI 完全离线且结果确定；每项失败能定位到角色与场景；在线评估不接触真实用户聊天；
角色质量改动同时提供基线对比、人工结论和成本/延迟影响。

## 阶段十二：性能、安全、同步与可复现发布（P2/P3）

目标：在角色能力增加后控制上下文、并发、资源与供应链风险，确保 PC 和 Android 可稳定交付。

- [ ] 建立提示词预算器，按角色卡、世界书、最近原文、角色状态、召回记忆和当前请求分配 token；
  超限时按明确优先级裁剪并写入脱敏诊断。
- [ ] 为每个平台维护上下文上限和输出预算；未知上限使用保守值，避免依赖错误字符串临时重试。
- [ ] 统一前台回复、后台摘要、主动消息、图片和 TTS 的任务队列、取消令牌和会话世代号，防止过期结果落库。
- [ ] 设定 PC/Android 的冷启动、内存、首段可见时间和长消息列表滚动预算，并在真机上记录 `p50/p95`。
- [ ] 检查 Android 后台/恢复、网络切换、系统杀进程和离线重试，确保不会重复发送主动消息或重复写入 turn。
- [ ] 为角色状态和未来独立记忆记录设计同步冲突可见性；自动合并不确定时保留双方版本并让用户选择。
- [ ] 编写威胁模型，覆盖导入角色卡、世界书、记忆、OCR/图片文本、供应商错误信息和同步负载中的提示注入；
  外部内容始终作为不可信数据，不能覆盖系统与用户边界。
- [ ] 清理日志和崩溃报告中的 Key、Authorization header、同步令牌、消息正文和本地绝对隐私路径。
- [ ] 将端到端加密列为独立 RFC：明确密钥恢复、换机、多端加入、搜索和服务器迁移方案；未实现前不得宣称 E2EE。
- [ ] 固定依赖、构建工具和签名证书指纹，生成 SBOM、校验和与可复现发布记录；Windows EXE、Android APK
  和 GitHub Release 使用同一版本号与提交。
- [ ] 发布前执行数据库迁移备份/恢复、完整 pytest、Ruff、Windows 打包、APK 构建、签名校验和实体机冒烟测试。

关键文件：提示构造与任务调度、同步协议/服务端、日志模块、Android 生命周期桥接、`packaging/`、CI 工作流。

验收：长会话不会无限增长提示；取消和切换会话无串写；日志与产物不包含秘密；旧客户端得到明确兼容结果；
同一 tag 的 EXE、APK、源码、签名和校验和可以互相追溯。

## 全局完成定义（Definition of Done）

每个后续 Issue 在标记完成前都应满足：

- [ ] 有明确的用户问题、范围、非目标、失败回退和 PC/Android 差异说明。
- [ ] 新能力默认值保守；高成本、实验性、联网或隐私相关能力可关闭并说明影响。
- [ ] 数据结构改动包含版本化迁移、备份/恢复、旧数据读取和必要的同步兼容测试。
- [ ] 不记录或上传 API Key、访问令牌、真实聊天正文、图片、音频和隐藏规划；确需处理时先取得用户明确同意。
- [ ] 至少包含单元测试、失败路径、取消路径和一项端到端工作流测试；角色质量改动另附回归样例。
- [ ] 不因图片、TTS、摘要或其他辅助服务失败而丢失已成功的文字回复。
- [ ] 设置项有清楚的名称、默认值、作用范围和恢复默认入口，旧设置升级后行为可预测。
- [ ] 更新 README、用户文档、变更日志和版本检查；涉及发布时完成 EXE/APK 签名与校验。
- [ ] 提供可量化的验收结果，包括质量、延迟、调用次数、资源占用或失败率中的相关指标。

## 明确的非目标

- 不把隐藏关系状态做成诱导使用的数值养成或付费机制。
- 不默认对所有轮次执行双模型调用，也不为“更聪明”无限增加上下文和后台请求。
- 不存储、同步或展示模型自由文本思维链；只保留业务所需的有限结构化状态。
- 不强制使用云端记忆、向量数据库或桌面专属原生依赖，Android 必须有等价的轻量降级路径。
- 不在未经同意时上传诊断、聊天、角色卡、图片、音频或设备信息。
