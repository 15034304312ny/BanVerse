# 文本模型职责、能力协商与降级

BanVerse 将文本调用分成“主角色模型”和“辅助任务模型”，两条路由共用现有
DeepSeek/GRS AI 凭据，但可以选择不同平台与模型。

## 职责边界

主角色模型负责所有用户可见的角色表达：用户消息回复、开场白、主动消息和随机新角色的首轮表达。
应用不会在后台静默更换这些内容的说话模型。

辅助任务模型当前负责：

- 会话列表摘要；
- 角色连续性状态与轻量记忆候选；
- 角色是否应当自主发图的语义判断。

主动消息的静默、冷却、每日上限、用户边界、敏感场景和双端幂等均由本地确定性策略与服务端
租约处理，不增加隐藏模型调用；通过门禁后的可见正文仍由主角色模型生成。头像提示词由本地
确定性模板生成。未来增加规划器时必须继续遵守“规划走辅助、可见正文走主角色”的边界。

## 兼容与回退

旧数据库没有 `aux_text_provider` 时按 `inherit` 处理，即辅助任务跟随主角色平台和会话模型，升级后
行为与调用平台不变。

显式选择另一辅助平台时：

1. 该平台凭据可用：使用辅助平台及辅助模型；
2. 该平台凭据缺失：回退到主角色平台和当前会话模型；
3. 两个平台都不可用：跳过本次辅助任务；
4. 辅助请求超时、返回空结果或解析失败：保留已经成功的角色正文，后台状态标记为待重试。

## 能力协商

统一能力描述包含文本、视觉、推理、流式、上下文长度和采样参数。平台未声明上下文长度或模型不在
本地缓存时显示“未声明”，不会猜测数值。

- DeepSeek 非思考模式：可发送 `temperature` 或 `top_p`；
- DeepSeek 思考模式：不发送采样参数；
- GRS AI 已知普通聊天模型：保持旧版 `temperature` 兼容；
- GRS AI 其他可选参数：只有模型目录明确声明时才发送；
- `frequency_penalty`、`presence_penalty` 与 `repetition_penalty`：当前平台没有声明有效支持，应用不发送。

“使用平台默认值”不会覆盖供应商默认采样值。推荐创造性模式保持旧版本角色会话的
`temperature=1.3`，但仍会经过模型能力过滤。

## 配置字段

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `text_provider` | `deepseek` | 主角色平台 |
| `default_model` | `deepseek-v4-flash` | 新会话主角色模型 |
| `grsai_text_model` | 平台默认 | 主角色使用 GRS AI 时的实际模型 |
| `aux_text_provider` | `inherit` | `inherit` / `deepseek` / `grsai` |
| `aux_deepseek_model` | `deepseek-v4-flash` | 独立 DeepSeek 辅助模型 |
| `aux_grsai_text_model` | 跟随主 GRS 模型 | 独立 GRS AI 辅助模型 |
| `roleplay_sampling_mode` | `temperature` | 推荐创造性 / 平台默认 / `top_p` |
| `roleplay_temperature` | `1.3` | 推荐创造性数值 |
| `roleplay_top_p` | `0.90` | 仅模型声明支持时发送 |

配置继续存放在跨 PC/Android 共用的 SQLite 设置表，不需要数据库结构迁移。
